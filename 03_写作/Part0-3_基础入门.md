# PART 0：工作方式转换——从"问 AI"到"把工作交给 AI"

> 先导图：三个能力维度与工作方式跃迁图（待插入 F01）

> **全书总主线**（本教程每一章都沿这条线走，先记住，后面反复用）：
>
> **定义任务 → 准备上下文与能力 → 执行 → 观察 → 验证 → 修复 → 交付 → 沉淀**
>
> **8 要素任务法**：目标 / 上下文 / 环境 / 权限 / 约束 / 过程 / 验收 / 交付。
>
> **四条铁律**（全书反复回来钉）：
>
> 1. 生成结果 ≠ 完成任务；
> 2. 执行动作 ≠ 得到正确结果；
> 3. 一次验证通过 ≠ 整体可靠；
> 4. Agent 声明完成 ≠ 实际完成。
>
> 旧的 Goal–Context–Resources–Capabilities–Workflow–Verification–Reuse（简称 GCRWV）模型全书废弃，不再使用。

## 0.1 本章要回答的只有一个问题

你已经在用某个聊天 AI：问一道题，它给一段答案；让它润色一段话，它给一段新文字。用久了心里会冒一个越来越大的问题：

> "它能不能不只回答我，而是真的把这件事做完？"

把下载文件夹里堆了三个月的八百个文件分好类；把老师发的二十篇 PDF 读完写成综述提纲；把一份乱码 Excel 清洗成能直接交作业的表。这些事不是"问一个问题"，是"完成一段工作"。

本章不讲产品百科。本章只帮你分清一件事——

> **你现在到底是在"问 AI"，还是已经把一段"工作交给了 AI"？**

分清这两件事，比背任何术语都重要。因为"问"和"交出去"，对你、对它、对风险的要求完全不同。

## 0.2 用三个维度看清你处在哪一步

不要去记"它是 Chatbot 还是 Agent"，那些标签是事后贴的。真正决定工作方式的，是下面这三件事，每一件都是一道开关：

**维度一：工具调用能力——它是只能说话，还是能动手？**

只能说话：它的全部输出就是一段文字，碰不到你的文件、点不了你的鼠标。
能动手：它能打开文件夹、读写文件、开浏览器、跑一段计算，把结果落成一个新文件。

**维度二：自主推进能力——每一步都要你发话，还是它能根据结果接着走？**

每步都要发话：你说一句，它动一下；你不说，它停在原地等。
能自主推进：你给一个目标，它自己决定先做什么后做什么，遇到中间结果会调整下一步，但在关键节点会停下来等你确认。

**维度三：持续运行能力——只跑这一次，还是能定时或被事件触发？**

只跑一次：你现在发一段、它跑一次，关掉对话就结束。
能持续运行：到点自己跑、收到一封带附件的邮件就自动处理、每天早上把昨天的网页变动整理给你。

把这三道开关画成一张对比表：

| 维度 | 弱（还在"问"） | 强（已经在"交活"） |
|---|---|---|
| 工具调用 | 只能生成文字 | 能操作文件 / 网页 / 软件 |
| 自主推进 | 每步都要你发话 | 能根据中间结果继续往下走 |
| 持续运行 | 只跑这一次 | 定时触发 / 事件触发 |

你现在用的那个工具，在这次任务上到底处于哪一格？照这三问过一遍，比问"它叫什么"准得多。

## 0.3 那些标签只是这三个维度的不同组合

你会听到 Chatbot、Copilot、Agent、Automation 这些词。它们**不是五个互不相干的类型，而是同一组能力开关被拨到不同位置后的组合**：

- 三道都弱：你只让它"问一句答一句"，它就是 Chatbot；
- 工具调用弱、其余辅助：它在 Word 侧边栏陪你写、在浏览器里总结当前页，活动范围被限定在那个软件里，这是 Copilot；
- 工具调用强、自主推进强、关键节点等人：你给它一个文件夹让它自己整理，这是 Agent，也是本教程的主角；
- 工具调用强、自主推进弱、按固定规则跑："收到带附件的邮件就存到云盘"，这是 Automation；
- 工具调用强、自主推进强、还能在跑的过程中根据中间结果调整、只在审批点等人：这是 Autonomous Workflow。

关键不是背这张表，而是明白一件事：**同一个产品，你今天只让它聊天，它就是 Chatbot；你明天给它一个文件夹让它自己整理，它就是 Agent。决定它落在哪一格的，不是它贴的标签，而是你这次交给它的任务要求它做到哪一步。**

## 0.4 什么事适合交、什么事不能放手

判断一件事适不适合交给它，不用背理论，过三问：步骤能不能拆成几步？对错能不能被看见、被检查？做坏了能不能撤销？三个都答"是"，就适合。整理文件、读论文做摘要、查资料存笔记、清洗一份表、按大纲出 PPT 初稿——都是这种"量大、重复、规则清楚、做坏了能删了重来"的活。

反过来，沾一条红灯就不能"交代完就走"：对错当场没法检查；做错撤不回来；后果落到别人头上。重大决策、给客户发邮件、公开发帖、调用真金白银的支付、改生产环境、Agent 嘴上说的事实没去核实——这些它只能给草稿，按按钮的必须是你。尤其是**删除、支付、公开发布这三类不可逆动作**，全书反复要求"先确认再执行"。

把它记成一句话：

> **Agent 是一个手脚很快、但需要你握着方向和刹车的助手。油门它可以踩，方向盘你握着，关键时候刹车你必须踩得下去。**

## 0.5 四条铁律从这里开始钉

本章最后，先把后面每一章都会回来钉的四句话写在这里，第一页就刻下来：

1. **生成结果 ≠ 完成任务。** 它吐出一段文字，不等于那段文字就是你要的成品。
2. **执行动作 ≠ 得到正确结果。** 它"做了"，不等于"做对了"。
3. **一次验证通过 ≠ 整体可靠。** 你抽查一处没问题，不代表其余三十处都没问题。
4. **Agent 声明完成 ≠ 实际完成。** 它说"我整理好了"，和文件夹里真的整理好了，是两件事。

这四条不是吓你别用它，而是告诉你：**它干得越快，你越要知道该在哪几个点上亲自看一眼。**

## 0.6 Mission L0：一次有目的的对话

> 难度 L0，纯对话，不碰文件。

**目标**：不产出任何文件，只让它把你脑子里那个模糊念头，问清楚、列出来。
**上下文**：你最近一直想做、拖着没开始的一件事，比如"这学期想把宏观经济学拿下"。
**过程**：新开一个对话，把下面这段原样发出去，替换方括号：

```text
我想做一件事：[用一句话说出来]。
我现在只告诉你这些。请你不要直接开始做，而是先反问我：
为了把这件事真正做成，你还需要我补充哪些信息？
把你需要我回答的问题列成清单，不要替我假设答案。
```

它反问一串问题，你逐条答，答不上来就说"这个我还没想清楚"。答完再说："基于我的回答，把这件事拆成 5 到 8 步，标出哪几步需要我再给材料。"把这份清单存成文本，这就是以后真做这件事的任务雏形。

**验收**：它列的步骤里至少有一步写明"需要你提供 XX 文件"；它没有替你决定时间、人数、预算这些你没提的事。如果它在反问里说"你应该是想要 XX 吧"，立刻纠正："我没说过这个，删掉。"

**失败照面**：你一上来就说"帮我做个民宿调研"，它直接给你一篇八百字报告——这叫答得快，没干活，因为它不知道你是交作业还是真开店。这一步的真正价值，是**在动手之前先发现"原来我还没想明白"**。

# PART 1：第一次让 Agent 进入你的工作环境

> 先导图：工作区、文件流向与四级权限示意图（待插入 F02）

> **一句话定位**：PART 1 给它桌子和钥匙，PART 2 告诉它到底干什么。
> 本章只解决一个问题——Agent 怎么进入你的工作环境：工作区在哪、文件怎么摆、原件和副本怎么分、输出放哪、权限给到哪、第一次真实执行怎么走。"到底要做什么"是 PART 2 的事，本章先把环境搭好。

---

## 1.1 本章只解决一件事

PART 0 你学会了"先让它问，别让它先做"。但对话里聊得再好，只要它不碰你的文件，就永远停在"嘴上干活"。本章让它第一次真的打开你的文件夹、读完材料、做出东西。你不需要懂技术，只搞清三件事：文件在哪、它怎么看得见、它能动到什么程度。

## 1.2 工作区：先把桌子摆好

几个词今天就要用，讲人话：

- **文件（File）**：你电脑里一个有名字的东西，PDF、Word、Excel、图片都行。
- **文件夹（Folder）**：装文件的抽屉，里面还能放子文件夹。
- **工作目录（Working Directory）**：本次任务的大本营。你告诉它"这次你就在这个文件夹里活动，别跑别处"。它是一道安全边界——圈定之后，它一般只在里面翻找和新建，不会自己跑到桌面、文档、别的项目里去。
- **输出目录（Output Folder）**：专门放"做完的东西"的子文件夹，成品统一丢这里，你找起来不用翻。

新手最常犯的错是把整个桌面当工作目录。圈得越大，它越可能翻到你不想让它碰的东西。**一个项目一个文件夹。**

## 1.3 原件与副本：本章最重要的一条规矩

**永远不要让它直接改你那份唯一的原件。** 正确摆法是：原件放 `原始材料/`，它要用的时候复制一份到 `工作中/` 去改。改坏了，原件还在。这条规矩在所有 Mission 里反复出现，现在先立住。

## 1.4 它怎么看到文件

按新手友好度，前两种就够用：

- **把文件拖进对话框**：最简单，它读完这次能处理，但新开对话不一定记得，文件太多一次拖不完。
- **指定一个文件夹作为工作区**（推荐，本教程默认方式）：较新的产品允许你"打开一个文件夹"作为本次地盘，之后它自己去里面翻，不用反复传。
- 再往后是云盘授权、从代码仓库（Repository / Repo）拉取，那是 PART 7、PART 8 的事，今天知道有就行。

## 1.5 四级权限：你允许它在你家里干什么

权限不是技术概念，是安全概念。从低到高四级：

| 级别 | 它能做什么 | 风险 | 你的态度 |
|---|---|---|---|
| 读 Read | 打开文件、读内容 | 几乎无 | 放心给 |
| 写 Write | 新建文件、改它自己建的文件 | 低，做坏了删掉即可 | 给，但限定在工作目录内 |
| 删 Delete | 删除文件、清空内容 | 中高，删了就没了 | 必须你事先知道，建议它先问你 |
| 对外发送 Send Out | 发邮件、发消息、发网页、调支付 | 高，动作不可逆 | 必须每次单独确认 |

好用的默认配置是：**读和写放开，删和对外发送一律先问你。** 别为了省事一开始就把全部权限打开——权限按需给，不是越大越好。

## 1.6 沙盒实测：四级权限各试一次

光看表不知道你手里这个产品在"删"和"覆盖"上靠不靠得住，只能亲手测一次。

**准备**：桌面新建文件夹 `权限实验_测试文件夹`，在里面手动建三个文本：`a_原件.txt`（写一行"这是原件，不要改我"）、`b_副本.txt`（复制一份改名）、`c_待删.txt`（写"这个待会儿要试删"）。全程只用这三个无关紧要的文件，绝不用你真正在乎的材料。

指定该文件夹为工作目录，依次发四段话，每段停下来观察：

第一步，读：

```text
请只读这个文件夹里的三个文件，把每个文件第一行念给我听。不要修改、不要删除任何文件。
```

第二步，写副本：

```text
请打开 b_副本.txt，末尾追加一行"这是被改过的副本"，保存。不要动 a_原件.txt 和 c_待删.txt。
```

第三步，尝试覆盖原件（重点观察它拦不拦）：

```text
请直接打开 a_原件.txt，把内容全部替换成"已被覆盖"，保存。
```

它是直接改了、还是停下来要你确认？直接改了，说明这个产品默认对覆盖原件不设防，以后你必须在任务里反复写"不许覆盖原件"。测完手动把 `a_原件.txt` 恢复成原来那行字。

第四步，尝试删除（重点观察它怎么处理）：

```text
请把 c_待删.txt 删除。
```

它是直接删了、还是先列出来给你确认？删完是进了回收站、还是直接没了？直接删且文件消失，说明这个产品在删除上不设防，以后凡涉及删除都要写"先列清单，我批准再删"。

把每一步观察追加进 `WORKLOG.md`（字段：日期 / 操作 / 涉及文件 / 结果 / 备注，模板见 `examples/WORKLOG.md`，里面有一次迷你文献调研的真实记录示例，照那张表填）。四级填完，你就有了一张属于自己这个产品的"权限行为表"。**后两步才是重点，舍不得让它真删、真覆盖，实验等于没做。**

## 1.7 Mission 1：整理一个混乱文件夹

> 难度 L1，单工作目录，无网络。

| 要素 | 内容 |
|---|---|
| 目标 | 把一个最乱的文件夹整理成结构清楚的样子，一个文件不丢。 |
| 上下文 | 你电脑里那个最乱的文件夹，通常是"下载"。 |
| 环境 | 只在这个文件夹里操作。 |
| 权限 | 可读、可新建子文件夹、可移动文件；**不要删除任何文件**；不碰该文件夹以外。 |
| 过程 | **先盘点、先提方案，我批准再移动**——重点是不能上来就动手。 |
| 验收 | 整理前后文件总数一致；随机抽三个子文件夹，内容和它说的一致。 |
| 交付 | 一份"分类说明.md"放文件夹根目录。 |

**动手前先备份**：把整个"下载"复制一份，命名 `下载_备份_20260918`，这一步你自己手动做，不交给他。然后指定工作目录，发：

```text
请你先只做两件事：
1. 列出这个文件夹里所有文件，按类型统计 PDF、图片、表格、压缩包、安装程序各多少个，哪些文件名明显重复。
2. 基于盘点提一个分类方案：建哪几个子文件夹、每个放哪类文件。
现在不要移动任何文件。把盘点结果和方案发给我，等我说"可以执行"再动手。
```

它回盘点表和方案，你审：有没有它想删的？有没有把重要文件归错类？你说"方案可以，但 XX 文件别动，其余执行"。做完你亲自打开文件夹抽查三个子文件夹，并数整理前后文件总数——必须一致。它建议删重复文件、清安装包，不要当场同意，先列出来你确认。

## 1.8 Mission 2：读多份 PDF 做摘要表

> 难度 L2，多文件，无网络。

| 要素 | 内容 |
|---|---|
| 目标 | 一次读完 5 份 PDF，做成一张摘要表。 |
| 上下文 | 挑 5 份你手头的 PDF，放进新文件夹 `课程阅读/`。 |
| 环境 | 工作目录就是 `课程阅读/`。 |
| 权限 | 可读 PDF、可新建 `摘要表.md`；**不改任何原始 PDF**。 |
| 约束 | 某份读不出来（扫描件、加密）就注明原因，**不要编**。 |
| 过程 | 先给表头方案，我确认后再写。 |
| 验收 | 表里正好 5 行；随机抽一份，它写的关键观点在原文里找得到；PDF 一个没被改。 |

发：

```text
工作目录是当前这个"课程阅读"文件夹，里面有 5 份 PDF。
请你：
1. 逐份阅读，不要跳读；每份单独一行，不要交叉总结。
2. 每份提取：标题、作者、出版时间（如有）、在讲什么（3 句）、3 个关键观点、1 个最该记住的结论。
3. 填成一张表，存为 摘要表.md，放本文件夹。
4. 不要修改任何原始 PDF。读不出来的那份，在表里注明"读不出，原因 XX"，不要编。
先不要写文件，先告诉我你打算怎么填表头，我确认后再写。
```

生成后随机挑一份 PDF，自己翻 5 分钟，对照那一行。多文件阅读最容易"串台"（把第 2 份和第 4 份混在一起）或"漏行"（说读完了表却只有 3 行），所以任务里要写死"每份单独一行""行数等于实际文件数，缺一份要说明"。

## 1.9 Mission 3：联网查资料并把脚印带回来

> 难度 L3，联网 + 文件。

| 要素 | 内容 |
|---|---|
| 目标 | 围绕一个陌生主题查资料，存成带真实链接的笔记。 |
| 上下文 | 一个你完全不懂、但最近要写点东西的主题，如"生成式 AI 对大学课堂的影响"。 |
| 环境 | 新建文件夹 `调研_生成式AI与课堂/`。 |
| 约束 | 所有链接必须是它真的打开过的；没打开的就不要写；来源优先官方 / 学术，不要自媒体。 |
| 过程 | 先报搜哪几个关键词，我确认后再搜。 |
| 验收 | 笔记里每条链接你都能点开且内容对得上；至少两个官方/学术来源；单独列一节"还没搞清楚的问题"。 |

发：

```text
我要写一份关于"生成式 AI 对大学课堂影响"的简短调研。
请你：
1. 联网搜索，优先大学官方文章、政府/教育机构报告、有出处的新闻、学术综述，不要营销号。
2. 找 6 到 8 个来源，至少来自 4 个不同网站。
3. 每个来源记录：标题、来源网站、发布日期、它说了什么（2 句）、原文链接。
4. 整理成 调研笔记.md，放工作目录。
5. 最后单独写一节"还没搞清楚的问题"，列 3 条没找到可靠答案的。
6. 所有链接必须是你真的访问过的。没真打开的，就不要写。
先告诉我你打算搜哪几个关键词，我确认后再搜。
```

生成后你亲自点开两三个链接核对。这是最容易"幻觉"的场景——它可能编一个看起来很真的 DOI，点开是 404。链接点不开或内容对不上，这条作废，让它重找。这一步累，但它是你以后一切联网任务的试金石。

# PART 2：把事情说清楚——8 要素任务法

> 先导图：8 要素任务法结构图（目标/上下文/环境/权限/约束/过程/验收/交付）（待插入 F03）

> PART 1 已经把桌子和钥匙交给它了。本章解决的是：**进了门之后，怎么把"到底干什么"说清楚，让它不用猜。**

---

## 2.1 为什么"帮我做一下"总会跑偏

最常见的发任务方式是："帮我把这篇论文写了。""帮我整理一下这个表。""帮我做个 PPT。"这些话的共同问题是——你只说了动词，没说对象、标准、边界，它只能猜。猜中是运气，猜不中是常态。

同样一个 Agent，有时做得特别好、有时完全跑偏，差别不在它那边，在你发的那段话。本章给一套可以背下来的方法：**8 要素任务法**。不是每次都写小作文，简单任务一两句话够；但只要这件事超过十分钟、涉及多个文件、做错要返工，8 要素就值。

## 2.2 8 要素定稿

从现在起全书统一用这 8 项，不再有"材料"和"背景"两套：

```text
1. 目标   （Goal）
2. 上下文 （Context = 材料 + 背景 + 当前状态）
3. 环境   （Environment）
4. 权限   （Permissions）
5. 约束   （Constraints）
6. 过程   （Process）
7. 验收   （Acceptance）
8. 交付   （Deliverables）
```

注意第二项的变化：**上下文不是单指"给了哪些文件"，而是材料、为什么做、前面做到哪、什么背景，三样合在一起**。下面逐项给你一个问题模板——发任务前，8 个问题都能答上来，任务就清楚了。

## 2.3 目标：把"想要"翻译成"可检查的结果"

> 问题模板：**我要最终得到什么？**

坏目标："帮我把这门课学好。"——什么叫学好？没法检查。
好目标："周末前，把这本教材第三章整理成知识结构图，覆盖全部小节，每小节一句话说清核心论点。"——有数量、有范围、有形式，你脑子里能想象出成品长什么样。

检查办法：把目标念给另一个同学听，问他"你觉得做完是什么样"。他的想象和你的不一样，目标就没写清楚。

## 2.4 上下文：弹药、背景、当前状态一起给

> 问题模板：**有哪些材料？为什么要做？前面做到哪？背景是什么？**

这一项三件事：材料在哪、为什么做、目前进展到哪。材料里哪些必读、哪些可联网补充，都写清。

坏做法："帮我写个综述。"它手里什么材料都没有，只能靠训练记忆编。
好做法："材料在这个文件夹：[拖进来]，`01_政策文件.pdf` 必读，`02_访谈记录.docx` 补充；这是课程作业，老师要求 3000 字、下周交；我已经有半页草稿在 `旧草稿.md`，在它基础上扩，不要从零重写。"

材料给太少它会编，给太多它会被无关信息带乱。别把整个硬盘拖给它——只给本次任务相关的那几份。"为什么做"和"做到哪了"尤其重要：这决定它是补做还是重做。

## 2.5 环境：圈定活动范围

> 问题模板：**在哪个项目 / 文件夹 / 系统中工作？**

坏做法：不说。它可能在你电脑上到处翻，或者反过来——你以为它能读本地文件，其实根本没接上。
好做法："你只在 `D:\课程\论文项目\` 这个文件夹里工作，新文件建在这里，不要动这个文件夹以外的任何东西。"

本质是画安全圈。圈定了，它再怎么折腾也在圈里。

## 2.6 权限：分级授权，写出来

> 问题模板：**允许读 / 写 / 执行什么？**

PART 1 讲过读、写、删、对外发送四级。在任务里直接写出来，不要假设它知道默认配置是松还是紧：

```text
权限：可读本文件夹所有文件；可在本文件夹新建和修改文件；
不要删除任何已有文件；不要往外发任何东西；
需要访问本文件夹以外的东西，先问我。
```

## 2.7 约束：把红线写出来

> 问题模板：**哪些绝对不能做？**

权限说"你能做什么"，约束说"你不能做什么"。常见红线：不得编造文献、作者、DOI、数据；不得覆盖原始文件；未经确认不得删除；不得把文件传到你不确定的第三方；中文写作不夹大段英文（术语除外）。写得越具体返工越少，"不得编造"对学术类任务每次必写。

## 2.8 过程：按什么顺序、哪里停下来

> 问题模板：**按什么顺序？哪里停下来等我？**

坏做法：不写顺序，它可能一上来就写结论，写一半发现材料不够。
好做法："先盘点材料，再建一张表，再按表读，最后根据表写。每做完一步停下来告诉我。"

复杂任务最怕跳步。但过程不要写太死——大顺序固定，中间允许它"遇到异常先报告"。

## 2.9 验收：怎么证明正确

> 问题模板：**怎么证明它做完了、做对了？**

这一项最容易漏，却是全书灵魂。坏做法："做完了告诉我一声。"它当然会告诉你。好做法：

```text
验收标准：
1. 摘要表里每条论点都能在原文找到出处；
2. 联网资料每条结论后跟一个我能点开的链接；
3. 表格行数必须等于实际文件数，缺一份要说明；
4. 最后单独列一节"没解决的问题"。
```

验收越具体，越不容易"假完成"。记住铁律第四条：它说完成了，不等于完成了。

## 2.10 交付：最后必须得到哪些文件

> 问题模板：**最后必须得到哪些文件？放哪里？**

坏做法："做好了发给我。"它可能把结果贴在对话框里，你还得复制半天。
好做法："最终交付三样：`综述草稿.docx`、`证据矩阵.xlsx`、`引用核验表.md`，全部放在工作目录的 `交付/` 子文件夹。"

价值是成品和过程分开：中间草稿留 `工作中/`，干净成品进 `交付/`。三周后回来找东西不乱。

## 2.11 六类任务速查（可直接改）

下面六段话，按你的任务类型挑一段，改括号里的内容。每段都把 8 要素压成了最必要的几项。

**整理文件夹**：

```text
目标：把"下载"按类型分好类。
上下文：D:\Downloads 里的所有文件。
环境：只在这个文件夹操作。
权限：可读、可建子文件夹、可移动；不要删任何文件。
约束：原始文件一个不能少；重名保留两份，不要合并。
过程：先盘点给分类方案，我批准再移动。
验收：整理前后总数一致；我随机抽三个子文件夹。
交付：一份"分类说明.md"放根目录。
```

**复习一门课**：

```text
目标：两周内把 12 个课程 PPT 整理成可复习的知识地图。
上下文：课程文件夹里 12 个 PPT + 我的课堂笔记.md。
环境：课程文件夹，新文件放"复习/"子目录。
约束：不要编造 PPT 里没有的概念；看不懂标出来，不要猜。
过程：先逐个 PPT 提取要点，再合并成地图，再标出笔记没覆盖的知识点。
验收：覆盖全部 12 次课，每次至少 5 个要点，每个要点能在原 PPT 找到。
交付：复习/知识地图.md + 复习/待补清单.md。
```

**文献综述初稿**：

```text
目标：写一份"生成式 AI 与知识劳动"综述初稿，3000 字左右。
上下文：工作目录里 20 篇论文 PDF + 我的已有综述草稿.md。
环境：只在本文件夹工作。
权限：可读、可新建；不改原始 PDF 和我的草稿。
约束：绝对不得虚构论文、作者、期刊名、DOI、数据；引用必须来自真实 PDF；没读的正文里标"待补"。
过程：先做证据矩阵，再梳理脉络，再列大纲，我确认大纲后写正文，最后逐条核验引用。
验收：每个引用都能在证据矩阵找到；附"未解决问题清单"。
交付：综述正文.docx + 证据矩阵.xlsx + 引用核验表.md。
```

**分析 Excel 写报告**：

```text
目标：分析销售数据 Excel，找出三个最值得关注的现象，写一页报告。
上下文：销售数据_2025.xlsx。
约束：不要编数字；所有结论能从表里算出来；数据有缺失先报告再分析。
过程：先读表结构，再数据质量检查，再描述统计，再出两张图，再写结论。
验收：每个数字能在 Excel 复算；两张图和结论对得上。
交付：分析报告.docx + 两张图.png。
```

**清洗乱表**：

```text
目标：把原始表.csv 清洗成规范表。
环境：工作目录；新建"清洗后表.csv"，不覆盖原始表。
约束：清洗规则先列给我看，我同意再动手；不删任何行，有问题的行标黄。
过程：先列问题清单（空值/重复/格式混乱），再给规则，确认后执行，最后报前后行数对比。
验收：清洗后行数 = 原始行数 - 明确剔除的重复行数；每条规则都在规则清单里。
交付：清洗后表.csv + 清洗规则说明.md。
```

**改一个小功能**：

```text
目标：把网页示例里的按钮文案从"提交"改成"立即报名"，手机上也正常显示。
上下文：工作目录里的网页项目文件夹。
环境：只在本项目文件夹操作；不联网装新东西。
约束：改前先备份原文件；一次不超过改 3 个文件；改完本地打开看一眼。
过程：先找到按钮在哪个文件，先备份，再改文案，再改手机样式，最后浏览器预览。
验收：本地打开按钮文案是新的；手机窗口下不溢出。
交付：改好的文件 + 一份"改了哪几个文件、改了什么"的说明.md。
```

## 2.12 好任务与坏任务对照

| 坏任务 | 缺了什么 | 好任务 |
|---|---|---|
| "帮我把这篇论文写了。" | 没材料、没字数、没标准 | "基于工作目录里 20 篇 PDF，写 3000 字综述初稿，引用必须真实，先列大纲给我确认。" |
| "帮我整理一下文件。" | 没说整理成什么样、放哪 | "把下载按类型分 5 个子文件夹，先盘点给我看，总数一个不能少。" |
| "帮我查查这个公司。" | 没说查什么维度、多深 | "查 XX 公司主营业务、近三年融资、主要客户，找 8 个来源每条带链接，存成 md。" |
| "帮我做个 PPT。" | 没说主题、页数、给谁看 | "根据这份大纲做 12 页课程汇报 PPT，学术风，每页不超 30 字，先出封面和目录给我看。" |
| "分析一下这个 Excel。" | 没说要什么结论 | "这份销售表里，找出销售额最高的 3 个品类和环比下滑最厉害的 2 个，数字能复算，写一页报告。" |
| "帮我翻译一下。" | 没说保留什么、格式 | "把这段英文摘要翻成中文，保留原文方括号引用格式不动，术语首次出现中英对照。" |
| "你自己看着办。" | 把判断权全交出去 | "我拿不准的你来提议，但删除、发送、公开发布这三类必须先问我。" |
| "快点做完。" | 没说什么叫完 | "做完的标准是：交付一份我打开就能直接用、不需要你再解释的文件。" |

## 2.13 从这一章长出两条主线

**学习线**：从"帮我学宏观经济"这个模糊愿望，套 8 要素后变成——材料是 12 份 PPT、目标是知识地图、验收是随机抽查能在原文找到。这就是 PART 0 Mission L0 那份问题清单的正式落地。

**科研线**：从"帮我写综述"变成——材料 20 篇 PDF、红线是不许编引用、流程是证据矩阵→脉络→大纲→正文→核验、交付是三件套。这是后面 PART 3、PART 4、PART 5 所有科研任务的母版。

简单任务先只加三件事就够："工作目录在哪""不要删原始文件""做完我怎么检查"。写满二十次复杂任务，8 要素会自动出现在你脑子里。

# PART 3：状态管理——让长任务不会断片

> 先导图：长任务状态仪表盘（待插入 F05）

> 本章的中心概念从"维护一堆文档"换成一个词：**State（状态）**。
> 它指的是——这个长任务现在进行到哪、下一步做什么、什么卡住了、为什么这么决定，这些信息的总和。PART 6 讲 Agent 内部怎么管 State，本章讲你在工作目录里怎么把它落地成几份看得见的文件。

---

## 3.1 本章要解决的新问题

前面的任务都不大：整理文件夹、读五份 PDF、查一个主题。但课程论文要读 30 篇文献写一个月，创业项目要调研、做表、写报告、改五版——这是**长任务**。交给 Agent 后你会遇到：

- 它做了一半，你不知道进行到哪了；
- 做了三天，它说"我忘了最开始要什么"；
- 中途想加一份新材料，不知道怎么接；
- 出来一堆中间文件，分不清哪个是最新的；
- 它跑着跑着重复劳动，同一件事做两遍。

先说清楚一个用词。这里常说"它会忘"——**这不是说模型像人一样真的记性变差，而是指：隔了一阵、或新开一个对话之后，之前那些对话里的信息没有进入当前模型上下文（Context Window，一次对话能同时容纳的文字量），所以它"看不到"了。** 解决办法不是求它记住，而是把状态写到文件里，让它每次开工先读文件。

## 3.2 为什么不能一口气做完

三个客观限制，不是它不够聪明：

**一次能"看到"的内容有限。** 上下文窗口就像一张桌子，面积有限，30 篇论文一次堆上去摊不开。
**任务本身有先后依赖。** 没读完文献就写综述，写出来也是编的。
**错得越早，改得越便宜。** 它一口气写八千字你才看，方向错了全废；写五百字就停下来给你看，你一句话就拉回来。

所以长任务的核心不是"让它一口气做完"，而是**拆小、分步、勤看**。

## 3.3 最小配置：三份就够

不要一上来就搭一套项目管理。**普通长任务，工作目录里只需要三份东西：**

```text
你的项目/
  TASKS.md        ← 任务清单：拆成可勾选的小项，做完一项勾一项
  WORKLOG.md      ← 操作流水：每做一步追加一行，记录它实际做了什么
  output/         ← 成品目录：最终交付物统一放这里
```

三份各管一摊，合起来就是 State 的全部：

- **TASKS.md** 管"事还剩什么没做"。状态约定：`[ ]` 未开始 / `[~]` 进行中 / `[x]` 已完成 / `[!]` 卡住。模板见 `examples/TASKS.md`，里面有一次迷你文献调研的真实勾选示例，照着填。
- **WORKLOG.md** 管"它的手实际做了什么"。字段：日期 / 操作 / 涉及文件 / 结果 / 备注，失败的步骤也要记。模板见 `examples/WORKLOG.md`，末尾有空表可直接复制。
- **output/** 管"做完的东西在哪"。

为什么是这两份文档而不是对话？因为对话会被新对话冲掉，文件不会；对话可以断，文件不会断。每次开工让它先读 TASKS.md 和 WORKLOG.md，它就知道从哪接着走。

## 3.4 复杂项目再追加三份

任务真的变重了（跨周、多人、有过返工方向），再慢慢加这三份，不要一开始就堆满：

- **DECISIONS.md**：专记"为什么这么定"，不是记做了什么，是记当时为什么放弃另一个方案。模板见 `examples/DECISIONS.md`。
- **README.md**：这个文件夹里都有什么、每个文件干嘛的。三天后的你自己也是"新人"，先读它。
- **CHANGELOG.md**：版本变更。"v1→v2：结论从'影响显著'改成'影响有限'，因为第 14 篇文献证据相反。"

## 3.5 不要为了项目管理而项目管理

这是本章最该记住的一句：**这些文件是为了让任务不断片，不是为了让你像项目经理一样打勾。** 任务短，就两份文档一个 output；真长到跨周再追加。看到 `论文_final.docx`、`论文_final2.docx`、`论文_真的最终.docx` 满天飞，就用编号 `初稿_v1.docx`、`初稿_v2.docx`，旧版本留着不删，CHANGELOG 记每版改了什么。

## 3.6 计划与停顿：先让它列，你再改

不要自己拍脑袋列计划。让它先列，你再改：

```text
我要做的事：[一句话目标]。材料放在 [文件夹]。
请你不要开始做。先给我一份计划：
1. 把这件事拆成 6 到 10 步，每步写清要产出什么；
2. 标出哪几步必须停下来等我确认；
3. 标出哪几步依赖前一步的结果。
计划发给我，我改完再开始。
```

它列计划的过程本身就是暴露问题——它列出来的步骤里漏了"读文献"直接跳到"写综述"，你一眼能看出来。

停顿分两档：**里程碑（Milestone）**是大节点，每个都对应一个你必须介入的动作（"文献盘点完，你确认哪些必读""大纲定了，你点头它才写正文"）；**检查点（Checkpoint）**是更密的小停顿，读 30 篇就每读 10 篇停一次，让你抽查质量——它从第 3 篇读偏，你在第 10 篇就能发现。**没有你介入的节点不叫里程碑，叫它自言自语。**

## 3.7 中断了怎么续：WORKLOG 与 TASKS 是断点

最难受的不是慢，是任务做到一半突然断了——网络抖了、会话过期、你误关窗口。这时最慌的是：做完的会不会白做？下一步从哪走？

答案还是那两份文件。**先别慌，别把原任务重发一遍**（重发 = 它把做过的又做一遍，还可能覆盖中间文件）。先做三件事：

1. 打开 `工作中/`，看已有哪些文件、哪个最新；
2. 打开 `WORKLOG.md`，看最后一行记的是哪一步——那就是断点；
3. 打开 `TASKS.md`，看最后一个没勾掉的是哪项——那就是下一步。

新开一个对话，把断点喂给它：

```text
我们的任务中断了，工作目录是 [路径]。
请你先读这三份文件，不要开始任何新动作：
1. WORKLOG.md —— 之前实际做了哪些步骤、最后停在哪；
2. TASKS.md —— 哪些已完成、哪些还没做；
3. 工作中/ 里最新的中间文件。
读完告诉我：上次精确断在哪一步（引用 WORKLOG 最后一行）、下一步做什么、有没有卡住待我决定的。
你说完，我确认后再继续。
```

确认断点无误后再让它续跑：

```text
断点确认无误，从 TASKS.md 第 [N] 项继续。
1. 不要重做已经打勾的步骤；
2. 做完一项把 [ ] 改成 [x]；
3. 每做一步往 WORKLOG.md 追加一行；
4. 发现之前某个中间文件是错的，先告诉我，不要直接覆盖。
```

`WORKLOG` 是"它的手"做过的事，`TASKS` 是"事"还剩什么，`DECISIONS` / `PROGRESS` 管"为什么这么走"。三份合起来，就是一串不会断的实物锚点——这就是 3.1 说的 State 落地：**对话可以断，文件不会断。**

（按日的进度流水记法见 `examples/PROGRESS.md`，需要时再用，不必一开始就开。）

## 3.8 中途改需求、加新材料

长任务几乎一定改需求。别直接在旧任务上接一句"不对，改成 XX"，要说清哪些保留：

```text
任务变更：原计划第三步写大纲，现在改为大纲写完后先加一步"找一份最新文献补进证据矩阵"，再写正文。
前面已做的（01、02）保留，不用重做。
请更新 TASKS.md 和 WORKLOG.md，告诉我新计划。
```

中途找到重要新文献也别甩一句"加进去"。关键是第三条——**新材料只增量处理，不要触发它重写一切**：

```text
新材料：我刚放进工作目录的 new_paper.pdf，2026 年最新文献，和主题直接相关。
请你：1. 单独读这一篇填进证据矩阵；
2. 判断它对现有大纲的影响——支持就加一条引用，反驳就标出来我们再讨论；
3. 不要重写已经写完的部分，除非我明确说改。
```

防止重复劳动还有一句必须养成习惯：每次开工前让它先读 TASKS.md 和 `工作中/`，然后问"基于已有进度，下一步是什么"，并在任务里写"已有中间成果先读，不要重做"。

## 3.9 Mission：跑一条两阶段长任务

> 难度 L5，长任务，含中间检查。

**目标**：用本章方法跑完"搜索→筛选→阅读→建表→小结"五阶段，中途至少停两次。
**上下文**：一个你真感兴趣的小主题，如"短视频对大学生注意力的影响"。
**环境**：新建工作目录，里面先放好 TASKS.md 和 WORKLOG.md 两份空模板。
**过程**：五阶段，搜索完停一次给我看候选清单，筛选完停一次给我确认入选，再开始阅读建表。
**验收**：中途至少停两次且你都给了反馈；TASKS.md 和 WORKLOG.md 真的按记录更新了；证据表里每条链接能点开；隔一天新开对话，你能靠读文件接上。

发：

```text
主题：[你的主题]。工作目录：[新建文件夹]。
计划：把主题拆成搜索、筛选、阅读、建表、小结五阶段。
搜索完成后停一次，把候选清单给我；筛选完成后停一次，把入选清单给我确认；然后再阅读建表。
全程在 TASKS.md 里勾进度，每做一步往 WORKLOG.md 追加一行。
所有结论必须有来源链接，不许编。
```

忍住别催它"快点做完"。它停下来的每一次，都是在帮你少返工。跑完随机挑证据表一条，点链接读原文，看它写的结论是不是原文真说的。
